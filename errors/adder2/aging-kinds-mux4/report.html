A hard error is a configuration cell that never takes a write again — aging or latch-up rather than a cosmic ray. It is the regime where the classical answers stop working by construction: a scrubber writes its golden copy back and the cells reject it, ECC decodes the right bits and cannot store them. Only a method that searches over the bits that still work has anything to do, and the rule never wanted the old bits back. boot means the cells were already dead when the rule started from random soft wires — can it assemble around them? repair means the rule grew a working circuit and only then did cells die.

The watchdog. An attempt that has not converged in 48 steps is abandoned: the configuration is re-initialised to soft wires with the frozen cells still frozen and the rule assembles a fresh circuit around them, up to 48 attempts in all, alternating a start chosen around the dead cells with the plain relay start. Every configuration written is the rule's honest next one; none is a candidate scored and discarded. steps and writes below are summed over the attempts a repair needed.

sat is the compiler baseline: exact synthesis with the dead cells pinned (sim/baselines/sat.py), told only what a write-and-read-back probe reports, 8 draws per row, a 120 s clock. t/o: the solve ran out of time and wrote nothing. nosee: it returned an exact answer to the wrong problem, because the fault does not read back.

Both can be exact; what separates them is that the climber writes a speculative configuration to the deployed fabric for every candidate it tries, and the rule writes none.
